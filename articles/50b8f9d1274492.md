# はじめに

[前回の記事](https://zenn.dev/e_kaikei/articles/8aa3bebbe4ce91)で、WASMを活用したリバースプロキシ・APIゲートウェイである「Plecto」あらため「Plecto Proxy」の思想や選択、設計原則について記述しました。

Plecto Proxyのリポジトリはこちら☟

https://github.com/Kaikei-e/PlectoProxy

今回はTinyGoをwasip2を使って、Plecto Proxyでのカスタムフィルタの記述を可能にしたので、その記録です。
設計判断としてWASI 0.3のPlecto Proxyですが、TinyGoをwasip2で導入しています。
それはひとえに、ポリグロットなカスタムフィルタの実現と、ランタイムとゲスト言語側のWASI 0.3対応が整うのを待つという不確実性をなくすためです。


## WASI 0.3とTinyGoとの関係

本題に入る前に用語を整理します。APIゲートウェイのカスタムフィルタについて詳しく記載したいので、なるべく短く記述します。

<br>

`TinyGo`

- Goを、ある制約下（後述）のターゲットとしてコンパイルする、LLVMベースの代替コンパイラです
- 「ある制約下」とは、バイナリサイズを極端に小さく求められる環境で、標準ツールチェインとは別のサブセットをLLVMで出力します
- マイコンやWebAssemblyをターゲットとして利用されることが多いようです

### wasip2（WASI 0.2）とTinyGoの関わり

ここで前回の記事で記載した「Plecto Proxy」の弱点である、「WASMの成熟を待つ必要がある」という点が絡んできます。
wasip2(=WASI0.2)は`wasi preview 2`の略であり、実運用でも1年以上本番投入されているものの、まだプレビュー版です。
wasi**p3**(WASI 0.3)も出ていますが、p2からp3でComponent ModelのCanonical ABIが非同期処理の扱いを一級市民へと置くと同時に、破壊的変更を伴うもので、ホストとゲスト問わず全面移行が未完了だからです。そのため、ホストランタイムである `wasmtime`で対応・実装が進んでいても、ゲスト側である言語、例えばGo言語などは現段階では、標準コンパイラでGOOS=wasip3自体が提案段階にとどまっています。
WASI1.0への到達は2026年後半〜2027年前半を目指して開発をされているのですが、Plecto ProxyではWASI 0.3で非同期処理の扱いが一級市民へと変わったことを受けて、プレビュー版でも先取りをして実装を進めています。そのため、前述のwasip`0.2`と`0.3`のズレが生じます。

## TinyGoとカスタムフィルター生成までのフロー

```
WIT定義 (.wit)
   ↓ wit-bindgen-go generate
生成されたGoバインディング（cmパッケージに依存）
   ↓ 手書きのGoコードから呼ぶ/実装する
tinygo build -target=wasip2
   ↓
Wasmコンポーネント（.wasm）
```

## では、なぜwasi**p2**でTinyGoを入れるのか？

Plecto Proxyのカスタムフィルターを**Go言語で記述できる**ようになり間口が広がるためです。
多言語カスタムフィルターを目的としている`Plecto Proxy`は、Go言語側のwasi0.3対応を待たずに導入すべきと判断し、Go/TinyGoのWASI0.3対応時期という外部要因に左右されるよりユーザーへの提供価値を優先しました。
Goは自分も好きで良く使う言語です。また言語の人口も多いと思っているので、「ポリグロットなカスタムフィルタ記述が可能」と標榜する以上、Plecto ProxyがTier B（※1）に据えている言語（TinyGo）でも取り入れてみてどうなるか関心がありました。wasip2段階である早期に導入し、Plecto Proxy側の実装をWASI 0.3での成熟に伴って発展させることも目的です。

※1: Plecto Proxyでは、`plecto:filter` の interface だけを import する（WASI import ゼロの）フィルタコンポーネントをTier Aとしています。
デフォルトの deny-by-default Linker が追加の宣言なしに WASIが要らない言語は、Rust, C, Moonbitです。
対して、TinyGo（Go）は言語ランタイムがWASI 0.2の機能を要求するため、現時点でTier Bとして実装と詳細な判断を先送りしていました。


## 実装など

以下ざっとコードを見ていきたいと思います。

渡している権限は次の6つだけです。
これがインターフェースです。
- ログ
- 時刻
- KeyValue
- カウンター
- レート制限
- 設定値

前回の記事同様に契約（WIT）によって、このフィルターの能力は最小限に絞られています。deny-by-defaultの実践です。

```wrold.wit
package plecto:filter@0.1.0;

interface types {
    record header {
        name: string,
        value: string,
    }
    record http-request {
        method: string,
        path: string,
        authority: string,
        scheme: string,
        headers: list<header>,
    }
    record http-response {
        status: u16,
        headers: list<header>,
        body: list<u8>,
    }
    record request-edit {
        set-headers: list<header>,
        remove-headers: list<string>,
    }
    record response-edit {
        set-status: option<u16>,
        set-headers: list<header>,
        remove-headers: list<string>,
    }
    variant request-decision {
        %continue,
        modified(request-edit),
        short-circuit(http-response),
    }
    variant response-decision {
        %continue,
        modified(response-edit),
    }
    variant request-body-decision {
        %continue(list<u8>),
        short-circuit(http-response),
    }
}

interface host-log {
    enum level { trace, debug, info, warn, error }
    log: func(level: level, message: string);
}

interface host-clock {
    now-ms: func() -> u64;
}

interface host-kv {
    get: func(key: string) -> option<list<u8>>;
    set: func(key: string, value: list<u8>);
    delete: func(key: string);
}

interface host-counter {
    increment: func(key: string, delta: s64) -> s64;
    get: func(key: string) -> s64;
}

interface host-ratelimit {
    record acquire {
        allowed: bool,
        remaining: u64,
        retry-after-ms: u64,
    }
    try-acquire: func(key: string, cost: u64) -> acquire;
}

interface host-config {
    get: func(key: string) -> option<string>;
}

world filter-body-go {
    use types.{http-request, http-response, request-decision, response-decision, request-body-decision};

    import host-log;
    import host-clock;
    import host-kv;
    import host-counter;
    import host-ratelimit;
    import host-config;
    include wasi:cli/imports@0.2.0;

    export init: func();
    export on-request: func(req: http-request) -> request-decision;
    export on-request-body: func(body: list<u8>) -> request-body-decision;
    export on-response: func(resp: http-response) -> response-decision;
}

```

Go側から呼び出す際のコードはこちらです。
Plecto Proxyの`plecto:filter` WITワールドに対応したフィルターを、Go（TinyGo）で実装したものです。
フィルターの実装なので、意図的に簡単な処理にしています。
簡易的な例でありつつも、少しでも現実のシナリオに近づけています。

- 起動（`init`）
  - フィルターの起動とカウンタのインクリメントで、必須です
- リクエスト（`on-request`）
  - リクエストヘッダを見て分岐させています
  - パニックやレスポンスヘッダ追加、レート制限、リクエスト拒否を行っています
- リクエストボディ（`on-request-body`）
  - リクエストボディに`deny-body`という文字列があれば403でブロック、なければ全部大文字に変換して継続
- レスポンス（`on-response`）
  - `x-plecto-respedit`ヘッダがあればレスポンスヘッダを1つ追加


```go
package main

import (
	"fmt"
	"os"
	"strconv"

	hostclock "filter-hello-go/internal/plecto/filter/host-clock"
	hostcounter "filter-hello-go/internal/plecto/filter/host-counter"
	filterbodygo "filter-hello-go/internal/plecto/filter/filter-body-go"
	hostlog "filter-hello-go/internal/plecto/filter/host-log"
	hostratelimit "filter-hello-go/internal/plecto/filter/host-ratelimit"
	"filter-hello-go/internal/plecto/filter/types"

	"go.bytecodealliance.org/cm"
)

func hasHeader(headers []types.Header, name string) bool {
	for _, h := range headers {
		if eqFold(h.Name, name) {
			return true
		}
	}
	return false
}

func headerValue(headers []types.Header, name string) (string, bool) {
	for _, h := range headers {
		if eqFold(h.Name, name) {
			return h.Value, true
		}
	}
	return "", false
}

func eqFold(a, b string) bool {
	if len(a) != len(b) {
		return false
	}
	for i := 0; i < len(a); i++ {
		ca, cb := a[i], b[i]
		if ca >= 'A' && ca <= 'Z' {
			ca += 32
		}
		if cb >= 'A' && cb <= 'Z' {
			cb += 32
		}
		if ca != cb {
			return false
		}
	}
	return true
}

func oneHeader(name, value string) cm.List[types.Header] {
	return cm.ToList([]types.Header{{Name: name, Value: value}})
}

func init() {
	filterbodygo.Exports.Init = func() {
		hostcounter.Increment("init-calls", 1)
	}

	filterbodygo.Exports.OnRequest = func(req types.HTTPRequest) types.RequestDecision {
		hostlog.Log(hostlog.LevelInfo, "filter-hello-go: on-request")

		inits := hostcounter.Get("init-calls")
		hostlog.Log(hostlog.LevelInfo, "init-calls="+strconv.FormatInt(inits, 10))

		// Exercise the fat-guest minimal WASI grant (ADR 000063): TinyGo's runtime routes
		// fmt.Println/os.Stderr through wasi:cli stdout/stderr under the hood. This proves the
		// host's stdio bridge — not just the WIT host-log capability above — carries a real
		// TinyGo guest's output into host-log.
		fmt.Println("filter-hello-go: stdout probe")
		fmt.Fprintln(os.Stderr, "filter-hello-go: stderr probe")

		headers := req.Headers.Slice()

		if hasHeader(headers, "x-plecto-panic") {
			// Regression fixture for the host's trap-path log recovery (ADR 000063 F2/F5): write
			// a stderr line with NO trailing newline, then trap — proving the host still
			// recovers this unterminated line instead of losing it along with the discarded
			// instance.
			fmt.Fprint(os.Stderr, "filter-hello-go: panic probe (no trailing newline)")
			panic("filter-hello-go: intentional trap for host log-recovery test")
		}

		if hasHeader(headers, "x-plecto-addheader") {
			return types.RequestDecisionModified(types.RequestEdit{
				SetHeaders:    oneHeader("x-plecto-added", "1"),
				RemoveHeaders: cm.ToList([]string{}),
			})
		}

		if rl, ok := headerValue(headers, "x-plecto-ratelimit"); ok {
			key := rl
			if key == "" {
				key = "default"
			}
			outcome := hostratelimit.TryAcquire(key, 1)
			if !outcome.Allowed {
				return types.RequestDecisionShortCircuit(types.HTTPResponse{
					Status:  429,
					Headers: oneHeader("retry-after-ms", strconv.FormatUint(outcome.RetryAfterMs, 10)),
					Body:    cm.ToList([]byte("rate limited by filter-hello-go")),
				})
			}
		}

		if hasHeader(headers, "x-plecto-block") {
			return types.RequestDecisionShortCircuit(types.HTTPResponse{
				Status:  403,
				Headers: oneHeader("x-plecto", "blocked"),
				Body:    cm.ToList([]byte("blocked by filter-hello-go")),
			})
		}

		return types.RequestDecisionContinue()
	}

	filterbodygo.Exports.OnRequestBody = func(body cm.List[uint8]) types.RequestBodyDecision {
		hostlog.Log(hostlog.LevelInfo, "filter-hello-go: on-request-body")
		b := body.Slice()
		if containsFold(b, "deny-body") {
			return types.RequestBodyDecisionShortCircuit(types.HTTPResponse{
				Status:  403,
				Headers: oneHeader("x-plecto", "blocked-body"),
				Body:    cm.ToList([]byte("blocked body by filter-hello-go")),
			})
		}
		up := make([]byte, len(b))
		for i, c := range b {
			if c >= 'a' && c <= 'z' {
				c -= 32
			}
			up[i] = c
		}
		return types.RequestBodyDecisionContinue(cm.ToList(up))
	}

	filterbodygo.Exports.OnResponse = func(resp types.HTTPResponse) types.ResponseDecision {
		if hasHeader(resp.Headers.Slice(), "x-plecto-respedit") {
			return types.ResponseDecisionModified(types.ResponseEdit{
				SetStatus:     cm.None[uint16](),
				SetHeaders:    oneHeader("x-plecto-respadded", "1"),
				RemoveHeaders: cm.ToList([]string{}),
			})
		}
		return types.ResponseDecisionContinue()
	}

	// Referenced so the linker cannot dead-code-strip the host-clock import (unused otherwise
	// in this conformance subset) — mirrors the other language ports touching every capability.
	_ = hostclock.NowMs
}

func containsFold(haystack []byte, needle string) bool {
	n := len(needle)
	for i := 0; i+n <= len(haystack); i++ {
		if eqFoldBytes(haystack[i:i+n], needle) {
			return true
		}
	}
	return false
}

func eqFoldBytes(a []byte, b string) bool {
	if len(a) != len(b) {
		return false
	}
	for i := 0; i < len(a); i++ {
		ca, cb := a[i], b[i]
		if ca >= 'A' && ca <= 'Z' {
			ca += 32
		}
		if cb >= 'A' && cb <= 'Z' {
			cb += 32
		}
		if ca != cb {
			return false
		}
	}
	return true
}

func main() {}

```

まだまだ、工夫をしなければフィルターを書きやすいという段階ではないですが、一旦の区切りまでは実装できたと思います。

## おわりに

今回はPlecto ProxyにTinyGoのサポートを追加しました。
TinyGoのサポートに伴って、wasip2の機能でどこまでをPlecto Proxyがカバーするのか、意思決定を重ねました。
例えば、フルのWasiCtx（fs / sockets 込み）でフィルターに能力付与する、という選択はしませんでした。前述の6つの能力だけです。
deny-by-default原則から外れるからです。

機能は追加するだけでなく、本質的なものに絞っていくべきだと[Alt](https://github.com/Kaikei-e/Alt)というマイクロサービスのRSSフィードリーダーを開発した際に学んだので、今回は慎重に機能の追加や設計上の取捨選択をしていきたいです。

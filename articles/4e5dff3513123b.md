# Docker Compose で動く、セルフホストのRSSリーダー・アグリゲーターを作る Part 1

[実際のコードはこちら。](https://github.com/Kaikei-e/Alt)

README.mdを見るとわかるがマイクロサービス群で構成されていて、ドキュメント混みでソースが70万行くらいあるので、十数回くらいに分けて記事にしていきたい。気が向いたら続ける形で、書いていこうと思う。

## Altとはなにか
> Alt は AI 拡張型 RSS ナレッジプラットフォームである。RSS フィードの収集・要約・分類・検索・定期レポート (Recap) 生成・RAG ベースの質問応答まで、情報消費の全ライフサイクルを統合的に支援する。

らしい。Claude CodeにAltのドキュメントを整備させた際に上記の通りに定義された。

## なぜ作ったか

- セルフホストのRSSリーダーが欲しかった。
- Feedlyは個人的には予算オーバーであった。
- Inoreaderは、比較的手ごろだが翻訳の精度に問題があった。
- RSSリーダーを作ることになんども挑戦していたが、毎回UIデザインなどで挫折していたので、そのリベンジとして取り組みたかった。

## なぜ書くか

- Cloudflare TunnnelとDocker Compose上で動くマイクロサービス群の開発と保守、運用をしてみて、得るものがあったため。
- Cursor、Claude Codeを活用し、今まででは到達てきないレベルの自作アプリを作成できたので、その経験に価値があると思ったため。

## 主要な機能

- RSSフィードの購読
- RSSフィードの自動収集
  - 定期実行
  - 同一ドメインに対してはレートリミット保証
- ユーザーのアクションによる記事の取得
- 記事の検索
  - MeCab トークナイザーによる日本語対応検索
  - 加えて、Meilisearchによる全文検索
- 記事に対するタグ付け
- 記事の要約と日本語への翻訳
  - Gemma3:4bの性能により英語から日本語はもちろん、多言語からの日本語への翻訳＆要約に対応（副産物）
- 過去数日分の記事をジャンルごとにまとめて分類し振り返る、Recap機能
  - 当初は7日分2000記事を処理していたが、品質やユースケースを考慮し、現在は過去3日分を振り返る仕様に変更。
- RAGによる最新情報へのアクセス
- TTS 音声合成で耳で情報接種できる機能
  - Kokoro-82M による日本語記事の読み上げ
- OTel準拠の自作ログサイドカーとClickHouseによるロギング
- GrafanaやPrometheusによる死活監視


## アーキテクチャや開発プロセス

- 基本的にクリーンアーキテクチャを採用した。
- マイクロサービスアーキテクチャを採用した。
- 特定の言語にこだわらない。使いたい言語や適する言語を選んだ。
- TDDで品質を保証した。
- GitHub ActionsによるCIでデグレを検知する。
- ADRを導入し、記録を残す。
  - 途中からADRの必要性を認識したため。

## 意識したこと。していること。
- とにかく速く、確実に動作すること
  - 自身の力不足や技術選定の甘さもあって、フロントエンドを作り直した。遅かったし、Lighthouseのスコアも低かったので、Svelte 5でのゼロからの再実装をした。
- LLMの支援によって、苦手なUIの品質も追求すること。
